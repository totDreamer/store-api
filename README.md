# Store API

Учебный backend-проект интернет-магазина на Python.

Проект развивается постепенно в процессе изучения backend-разработки: от простой доменной модели на чистом Python до полноценного REST API с базой данных, тестами и контейнеризацией.

## Цели проекта

Основная цель — практическое изучение Python backend-разработки на одном развивающемся проекте вместо набора изолированных учебных задач.

В процессе разработки планируется изучить и применить:

* объектно-ориентированное программирование;
* обработку исключений;
* аннотации типов;
* структуру Python-проектов и пакетов;
* разделение ответственности между моделями и сервисным слоем;
* PostgreSQL и SQL;
* SQLAlchemy;
* FastAPI;
* Pydantic;
* Alembic и миграции базы данных;
* pytest;
* асинхронное программирование;
* аутентификацию и авторизацию;
* Docker;
* развёртывание приложения.

## Текущее состояние

На текущем этапе реализована доменная модель интернет-магазина и сервисный слой с хранением данных в памяти.

Проект пока не использует базу данных: пользователи, товары и заказы хранятся в коллекциях экземпляра `Store` и существуют только во время работы программы.

### Product

Товар содержит:

* идентификатор;
* название;
* цену.

Реализованы:

* валидация входных данных;
* нормализация цены к `float`;
* неизменяемый через публичный интерфейс идентификатор;
* сравнение товаров по идентификатору;
* поддержка использования `Product` в качестве ключа словаря через `__eq__` и `__hash__`.

### User

Пользователь содержит:

* идентификатор;
* имя;
* email.

Реализованы:

* валидация входных данных;
* нормализация строковых значений;
* неизменяемый через публичный интерфейс идентификатор.

### Order

Заказ связан с пользователем и содержит товары с указанием их количества.

Реализованы:

* добавление товаров;
* объединение одинаковых товаров;
* автоматический расчёт общей стоимости;
* статусы `new`, `paid` и `cancelled`;
* оплата заказа;
* отмена заказа;
* запрет изменения закрытого заказа;
* инкапсуляция внутреннего состояния;
* неизменяемый через публичный интерфейс идентификатор.

## Сервисный слой

В модуле `store/services.py` реализован класс `Store`, управляющий доменными сущностями приложения.

На текущем этапе `Store` выполняет роль in-memory хранилища и предоставляет публичный интерфейс для работы с пользователями, товарами и заказами.

Реализованы:

* добавление пользователей;
* добавление товаров;
* поиск пользователя по `id`;
* поиск товара по `id`;
* поиск заказа по `id`;
* контроль уникальности идентификаторов;
* создание заказа для существующего пользователя;
* добавление существующего товара в заказ;
* обработка попыток обращения к несуществующим сущностям.

Данные хранятся в словарях:

```text
id -> User
id -> Product
id -> Order
```

Такое хранилище является временным учебным решением. После завершения работы программы его содержимое теряется. На следующих этапах проекта постоянное хранение данных будет перенесено в базу данных.

## Обработка ошибок

Все доменные исключения проекта наследуются от общего `StoreError`.

Текущая иерархия:

```text
StoreError
├── ValidationError
├── OrderOperationError
│   └── InvalidOrderStatus
└── StoreOperationError
```

### ValidationError

Используется при передаче некорректных данных доменным моделям или сервисному слою.

### OrderOperationError

Базовая категория ошибок недопустимых операций с заказом.

`InvalidOrderStatus` возникает при попытке выполнить действие, несовместимое с текущим состоянием заказа.

### StoreOperationError

Используется для ошибок операций сервисного слоя, например:

* попытки добавить сущность с уже существующим `id`;
* поиска несуществующего пользователя;
* поиска несуществующего товара;
* поиска несуществующего заказа.

## Пример текущего взаимодействия

На текущем этапе приложение используется программно:

```python
store = Store()

user = User(1, "Michael", "example@example.com")
product = Product(1, "Headphones", 10000)

store.add_user(user)
store.add_product(product)

order = store.create_order(order_id=1, user_id=user.id)
store.add_product_to_order(
    order_id=order.id,
    product_id=product.id,
    quantity=2,
)

print(order.total)
```

В дальнейшем ручные вызовы сервисного слоя будут заменены обработчиками HTTP-запросов: внешний клиент сможет создавать пользователей, товары и заказы через API.
